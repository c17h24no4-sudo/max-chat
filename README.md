# max-chat — веб-чат для мессенджера MAX (React + GREEN-API)

Тестовое задание «Фронтенд разработчик React». Простой веб-интерфейс по образцу web.max.ru: пользователь вводит учётные данные инстанса GREEN-API, создаёт чат по номеру телефона, отправляет текстовые сообщения и видит ответы получателя.

## Как это работает
1. **Вход.** Вводятся `idInstance`, `apiTokenInstance` и адрес API (по умолчанию `https://api.green-api.com`, свой адрес указан в личном кабинете GREEN-API). Данные проверяются методом `getStateInstance`: инстанс должен быть авторизован в MAX. Хранятся только в `sessionStorage` вкладки, на сервере не сохраняются.
2. **Новый чат.** Вводится номер получателя (`8 999 123-45-67`, `+7…` и т. п.), номер нормализуется и превращается в `chatId` вида `79991234567@c.us`.
3. **Отправка.** Метод `sendMessage` (`POST {apiUrl}/waInstance{id}/sendMessage/{token}`), только текст, до 4000 символов. Статусы сообщения: отправляется / отправлено / не отправлено.
4. **Получение.** Цикл `receiveNotification` (долгий запрос, 5 секунд) → разбор уведомления → `deleteNotification`. Принимаются входящие текстовые сообщения (`incomingMessageReceived`) и отправленные с телефона (`outgoingMessageReceived`); статусы и медиа пропускаются. Ответ привязывается к чату по номеру телефона отправителя (`senderPhoneNumber`), потому что MAX присылает в `chatId` свой внутренний идентификатор.
5. Чаты и сообщения сохраняются в `localStorage` (по `idInstance`), счётчик непрочитанных, дедупликация повторной доставки.

## Почему есть сервер (прокси)
Браузер не может вызывать GREEN-API напрямую: сервис не отдаёт CORS-заголовки (предзапрос получает 403, проверено). Поэтому запросы `/api/...` идут через небольшой Node-сервер (`server/server.mjs`), который пересылает их на адрес из заголовка `X-Api-Url`. Прокси разрешает только `https://*.green-api.com`, иначе он стал бы открытым прокси; токены не пишутся в журналы и не хранятся.

## Запуск локально
```
npm install
npm start            # сборка + сервер на http://localhost:8080
```
Для разработки: в двух терминалах `npm run server` и `npm run dev` (Vite проксирует `/api` на порт 8080).

### Данные GREEN-API
1. Зарегистрироваться на green-api.com, выбрать тариф «Разработчик» (бесплатный, до 3 чатов).
2. Создать инстанс MAX и авторизовать его (QR-код в приложении MAX).
3. Скопировать `idInstance` и `apiTokenInstance` в форму входа. Свой адрес API указан в карточке инстанса.

### Проверка без аккаунта
`npm run mock` запускает локальный мок GREEN-API (те же адреса и форматы, что в документации; «получатель» отвечает через 1,5 с). Для входа: id `1101000001`, токен `mock-token`, адрес `http://127.0.0.1:9099`; прокси нужно запустить с `ALLOW_API_URL=http://127.0.0.1:9099 npm run server`.

## Тесты (`npm test`, 30 тестов)
- нормализация номеров, разбор уведомлений (в том числе вариант без номера и не-текстовые), состояние чатов (дубли, непрочитанные, статусы);
- клиент GREEN-API на моке: отправка, получение, удаление, ошибка неверных данных;
- прокси: разрешён только `*.green-api.com`, чужой адрес получает 400, нет выхода за папку сборки;
- интерфейс целиком на моке: создание чата → отправка → ответ получателя виден в переписке; ошибка неверного номера;
- регрессия: в новом Chrome `scrollIntoView` возвращает Promise, и эффект React падал белым экраном (найдено при живой проверке, добавлен тест).
Проверено мутацией: если сломать дедупликацию или привязку ответа к номеру, тесты падают.

## Что не проверено
Живой обмен с настоящим MAX требует аккаунта GREEN-API и авторизованного инстанса: он проверен на локальном моке, повторяющем формат из документации. Если MAX присылает ответ без `senderPhoneNumber`, ответ попадёт в отдельный чат с идентификатором MAX (ограничение описано в коде `notifications.ts`).

## Стек
React 19, TypeScript, Vite, Vitest + Testing Library, Node (прокси без зависимостей).
